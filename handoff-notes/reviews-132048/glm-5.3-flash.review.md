## Findings
1. **major — tests/agent/test_relay_blocked_generator_interrupt.py** — uses `signal.SIGALRM` and `signal.setitimer` with no `@pytest.mark.platforms("posix")` marker. Per root `AGENTS.md` ("Use the marker, never a bare skipif"; `scripts/ci/list_os_marked_tests.py` imports unmarked files in every OS lane), this file will be imported on the Windows lane and fail at runtime (`signal.SIGALRM` does not exist on Windows). Fix: `@pytest.mark.platforms("posix")` on the test. (Cannot execute a Windows lane here — reasoning, but the API absence is a fact.)
2. **minor — agent/relay_llm.py:~359-419** — theoretical re-entry window on the queued-not-started worker: if the consumer lane is cancelled while a `to_thread` work item was dequeued but the worker has not yet acquired `close_guard`, `_close_when_safe` sees `reading == False` and calls `close()`; the worker then sets `reading` and calls `next()` on the generator being closed in another thread → `ValueError: generator already executing` surfaces only as an unretrieved future exception (the coroutine has already unwound). The window is nanoseconds wide and unreachable when the read was already in flight (that path defers correctly), and no coroutine-visible failure results. Fix if desired: have `_close_raw_stream` perform `run_callback(close)` while still holding `close_guard`? — not advised (close can block); a cheap alternative is setting `closed` and re-checking/deferring if a read started between check and close; or accept and document. Unverified at runtime — interleaving reasoning only.
3. **minor — agent/relay_llm.py:~362-367** — `_close_raw_stream` sets `closed = True` before `run_callback(close)` runs; if that call raises, the iterator is never closed and no retry is possible (flag already set). The deferred path logs; the inline path sets `_close_error`. Old code had the same single-attempt behavior, so not a regression — but the `closed` flag now also suppresses a hypothetical retry that the old code allowed on a later `close()` call. Suggested fix: set `closed = True` only after a successful close (re-check under lock), or on failure log a retry hint. Reasoning; no runtime proof.
4. **nit — tests/agent/test_relay_blocked_generator_interrupt.py:54** — file has no trailing newline; module docstring ("Bounded real-signal comparison...") reads like a test-plan fragment rather than describing the behavior under test.
5. **nit — website/docs/developer-guide/relay-managed-stream-ownership.md (rule paragraph)** — the stated invariant "only that worker may advance or close it" conflicts with the code's fast path, where the consumer lane closes the iterator when it is idle. The later "handshake" section describes both paths correctly; tighten the one-line rule to "only the thread not executing the iterator may close it."

## What is good
- Correct ownership model: `reading` set under the same lock before `next()` and cleared after, so a close can never race an executing generator on the exercised path; idempotent single close under `close_guard` prevents double-close; the deferred branch is the only legal closer mid-flight.
- Deferred close errors are logged, not swallowed silently, and are kept off the caller's path — the WHY is documented in both the commit message and the doc page (AGENTS.md style: comments carry the WHY, no speculative infrastructure, one logical change plus test and doc).
- `close()`/`_close()` semantics preserved: `_close_error` still surfaced on the inline path; lease and `_loop` released regardless of deferred-vs-inline (matches the doc's "Consequences to preserve").
- Doc page describes the code as written (verified against the diff line-by-line); `sidebars.ts` entry is alphabetically placed and the only sidebar edit.
- Test exercises the real path: real `relay_turn` fixture, real POSIX signal handler, asserts interrupt propagation, provider `finally` execution, worker-thread termination, and lease/loop release — and demonstrably fails on the parent commit with the exact issue symptom.
